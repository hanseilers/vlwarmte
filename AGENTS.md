## Learned User Preferences

- Before recommending a local dev URL, validate it: `curl` the URL from the same machine, expect `200`, `text/html`, body starting with `<!doctype` (or project `<title>`), and **not** a “Directory listing” page; if the port is already taken by another process, use another port and document it. A directory listing almost always means the server was started from the wrong working directory or the wrong process owns the port.
- Prefer clarifying questions one at a time (say how many remain) and use multiple-choice options when possible.
- Require explicit permission before creating new `.md` files (exception: short project `README.md` captions in `beeldmateriaal/projecten/<folder>/`).
- Dislikes using worktrees in general; only use them when they clearly help and can be justified briefly.
- Public site copy should not claim strict in-house-only delivery or “geen onderaanneming” when trusted subcontractors are part of execution; avoid unnecessary public detail about how work is staffed unless accurate and intentional.
- For Google Ads campaign creatives, prefer real customer/project photos from `beeldmateriaal/`; avoid AI-generated imagery (light editing like crop/brightness is fine).
- For VLWarmte warranty copy, describe pipe (buis) warranty as a straight “10 jaar garantie”; avoid “fabrieksgarantie” and avoid hedging with supplier/type conditions unless the user explicitly asks for that nuance.
- **Form & FAQ UX:** Contact/offerte form uses a vertical field pattern (label, optional hint, then input)—avoid side-by-side label+input rows with large spacers. FAQ/accordion question titles must be at least as prominent as the answer body.
- **CTA density:** Limit competing primary CTAs per page so actions stand out—especially on `diensten.html`; avoid packing many equal-weight buttons in hero + bands.
- Do not commit Formspree deploy keys or a tracked `formspree.json` that contains secrets; keep those files gitignored and ship only a safe `.example` template in the repo.
- **Proactive assistant:** Default to performing runnable steps immediately (shell, reads, edits, verification) instead of only telling the user what to run; offer or continue with the next actionable step when something still requires the human (secrets in their env, browser login, irreversible confirmations). For “today” / current-year questions in this workspace, treat the session **Today's date** field in user info as authoritative when present (do not assume a default training year). When the user has limited typing capacity, minimize repetitive manual entry—prefer gitignored `secrets/*.env`, short concrete commands, and scripted or agent-run setup. On UI changes: meaningful `alt` on icons/controls, `aria-expanded` on FAQ toggles, visible focus on custom controls; run Lighthouse on live `https://www.vlwarmte.nl` after substantive deploys (CDN/cache may shift scores).
- **Public copy tone (Noord-Nederland):** Informal and friendly (`je`/`jij`, not `u`/`uw`); plain language, not stiff or corporate. Avoid words like “realiseert”, “gevestigd”, and “werkzaam”; prefer “meestal” over “doorgaans”. Write reaction times as **één werkdag**, not “1 werkdag”.
